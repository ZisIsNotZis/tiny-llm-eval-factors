* **[METHOD, m9] Grader format must match the model's tool-call dialect, or you measure nothing.** BFCL's default `Qwen/Qwen3-1.7B` handler uses *raw prompting*: our Qwen3.5 model replied in prose and it scored **0.0%**. Two other harness bugs had to be fixed first: (a) llama-server with 4 slots gave only 16k ctx per slot vs BFCL's 40k requirement (114 context-overflow errors); (b) BFCL resumes from stale result files, so old 0% results were being re-scored. * **[INFRA, checkpoint] A multi-turn BFCL panel can silently re-score the previous quant's file — guard now in the driver.** `bfcl generate` defaults to `allow_overwrite=False`, so pre-existing entries are not regenerated, and the result path is keyed by the *handler*, not the run tag: the panels `qwen4b-q2` and `qwen4b-q3` share `Qwen/Qwen3-4B-Instruct-2507-FC` and therefore the same `result/<handler>/.../BFCL_v4_multi_turn_base_result.json`.
