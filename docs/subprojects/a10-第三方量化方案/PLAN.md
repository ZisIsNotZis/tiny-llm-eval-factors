## 判定口径（先写死，避免事后挑解释）

1. **一族 = 同一套 base 权重只换量化文件**。本层的族是 `Qwen3.8-27B`：五个文件的张量集合**逐项相同**（866 个张量名、元素数逐项相等、参数量 27,320,697,856 相同），所以「同一族」在这里是实测的，不是按文件名猜的。
2. **第三方档 = 文件名带 `GSQ-RCO` 的文件**；原生档 = 同一族里 unsloth `UD-` 配方的那三个（2.878 / 3.850 / 4.173 比特/权重）。原生阶梯的**有效位宽取 `.wrapup/bpw_map.json`**（`8 × 文件字节 ÷ gguf 精确参数量`），不取档位名、不取库里四舍五入的 `__size`。
3. **「最近原生档」= 位宽差绝对值最小的那个原生档**，逐档各算一次；**「插值档」= 把该第三方档的位宽夹住的两个原生档之间的线性插值**，并要求同时打印这两个原生档之间的段差（因为本族的原生阶梯**不单调**，见 `RESULT.md::ladder-own-step`；不单调时线性插值只是记账，不是预测）。
4. **区间 = 两比例差的 Newcombe method 10**，`n` 取该格自己的 `n_items`；与 `a03`/`a01` 同一个 home（`import curves`），不复制。**插值档的区间** = 两个被夹住的格的区间取并（保守：插值本身没有残差自由度，只有两个点，给不出插值误差），并在输出里明写这一点。
5. **不池化**：9 列逐列报，绝不跨列平均；也不把 100 题的子集与 164/378/912 题的格放在同一个判据下比较（`a03::AGENTS.md` 第 8 条、`i01` 的地板是逐族定的）。**60 题的探针不与 161 题的 MultiPL-E 格可比**：本族的第三方档在 MultiPL-E 列上**没有任何格**（`RESULT.md::unmeasured`），这就是「未测」，不是 0，也不许用别的族的 161 格代替。
6. **「未测」永远不是 0，而且配对缺一侧就叫「未测」**：第三方档有、原生档没有的列，差值是「未测」，不写 0、不写「无差」。
7. **测量与分析分开**：`kind: measured` 的事实只写机器读数；「该不该用第三方方案」这类判断写 `kind: analysis` 且标 `provisional`，并写否证条件。
8. **承载断言的证据必须随仓库走**：逐类/逐张量分配来自 `*.gguf`（不入库），所以冻结成 `analysis/fixtures/a10_map.json`，每个条目自带推导证据（文件字节数、参数量、张量数、逐类 bits）；`build_fixture.py --check` 用本机源做漂移检查，**缺源退出 2**。
9. **标签不能从档位名推定**：`GSQ-RCO` 是**上传者写的档位名**，不是本层证明过的机制；它到底对应哪种比特分配、与 `IQ3_XXS`/`Q3_K_XL` 这类名字是不是同一套命名，全部由 `WP3` 的实测轮廓回答。反过来，`mktables` 对这批文件名的解析结果（`split_quant` 返回 `None`、`scheme_class` 返回「原生 K」）是**事实**，`WP4` 要把它写出来：报告的分类器看不见第三方方案。
10. **单次运行**：本族每一格只有一次运行；`i01` 的确定性解码地板是 0 道题（四族 161/164/100/40 全同），所以同输入重跑不是噪声来源；但换文件就是换输入，`i01::res29` 的「未记录输入差可致 ±16/161」是本层必须写出来的外部约束。因此任何区间不含 0 的差只能说「该列分得开」，不能说「第三方方案更好」；跨列方向不一致时要按多重比较口径读。

5. **`report.html` 与 `mktables.py` 归 i02/meta**：本层只提交「应写成什么 + 否证条件」，不动生成器。
