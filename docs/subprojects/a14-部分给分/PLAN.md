## 里程碑：研究结束

- 终点状态：三件事同时有可复算证据——
  1. **可得性矩阵**：本项目用到的每个基准族逐族写明「逐测试通过比例能否从仓内既有产物推出来」，能推的写出从哪个字段、哪条命令推；不能推的写明缺哪个输入、补它要花什么（GPU 分钟或 CPU 分钟）。不许出现「大概可以」。
  2. **同完成物双 Y 对照**：在**同一批落盘完成物**上同时算二元 pass@1 与逐测试比例，给出两者的排序差异（哪些格对在二元下并列/差 1–2 题而在比例下分开，反之亦然），以及这种比较的噪声（判分侧重跑噪声、采样侧噪声）。
  3. **裁决**：把「二元 Y 是否丢了信号」落成一句话结论，并说清它在哪些格上成立、在哪些格上不成立，以及更细的 Y 在哪个方向上被采样噪声吃掉（`i01` 的 `res30` 已实测：temp>0 时逐题 Jaccard 0.53–0.67，比分数更敏感）。
- done 判据：`python3 "docs/subprojects/a14-部分给分/testfrac_audit.py"` 退出 **0**，且它在**干净 clone** 里也退出 0 —— 这一点和 `i01` 不同，是刻意的：a14 的输入全部是已入库的产物（`.wrapup/mres/*_eval.json`、`.wrapup/testfrac_*.jsonl`、`experiments.sqlite`），不需要 venv、不需要 GPU、不需要 `/tmp/MultiPL-E`，所以「clone 里跑不出来」在这里本身就是缺陷，不是可接受的限制。
  - 缺输入（少一个 `_eval.json`、少一个 testfrac 逐题文件、库不可读）时脚本必须 `exit 2` 并逐项打印缺哪个文件；`exit 0` 只表示「全部证据在场且都成立」。
  - 负控：把某一格的逐题文件改一行（把一道通过题标成不通过）再跑，检查必须变红；`--negative-control` 做这件事并在临时副本上执行，不碰真产物。
- 只有一个里程碑：它是用户同步点，之前不再切分。
