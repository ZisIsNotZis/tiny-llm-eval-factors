## 判定口径（先写死，避免事后挑解释）

1. **配对只在一族内**：一族 = 同一套 base 权重只换量化文件（`mktables.family_of`，保留尺寸）。跨族的同字节点不是受控比较。
2. **匹配字节的判据分三档写死**：`|Δbpw| ≤ 0.45`（报告第三节 / `mktables.MATCH_BPW` 的现行口径）、`≤ 0.15`（本层收紧）、`≤ 0.05`（字节几乎相同）。同一结论必须在至少两档下一致，否则写明只在哪一档成立。
3. **区间 = 两比例差的 Newcombe method 10**，`n` 取该格自己的 `n_items`；TruthfulQA 的 `acc` 是概率质量均值（`i01::res26`），那一列只报差值不套二项区间。区间是**非配对**（逐题结果没有落库），所以「跨 0」只能说测不出，不能说相等。
4. **配对前先验协议**：`protocol / n_items / ctx_size / parallel_slots / temp / reasoning` 逐列相等，不等即该格「不可比」并打印。
5. **承载断言的证据必须随仓库走**：来源与比特分配的唯一源（面板元数据、gguf 头）都不入库，所以它们各被冻结成 `analysis/fixtures/{vendor_map,alloc_map}.json`，每个条目自带推导证据（run_tag→路径 / 文件大小与参数数）。改判据时要同时改夹具，`build_fixtures.py --check` 用本机源对夹具做漂移检查。
6. **结论必须带探测下限**：跨族归因的「跨 0」不等于「没有效应」，每条这类结论都要写出该系数的半宽（`attrib.py` 的「识别来源与探测下限」块），措辞用「不可分辨」。
7. **厂商不可从文件名推断**：厂商取面板 json 里写入的模型绝对路径（`mscache/<vendor>/…` 或 `models--<vendor>--…`），文件名里的 `UD-` 前缀只说明上传者的**配方**（unsloth dynamic），不说明来源，而且 `Phi-4-mini-instruct-Q2_K.gguf` 就是反例（非 UD 命名、实际来自 unsloth）。
8. **`n_items` 先看再用**：`ifeval/gsm8k/arc/truthfulqa` 是 `limit 100` 的子集，`mmlu` 是 912，`humaneval` 164，`mbpp` 378；缺格写「缺」，不写 0。
9. **不池化**：语言、协议、基准之间绝不平均；跨族汇总只用计数与同号检验。

## 给 `report.html` 第三节的建议文本（`WP6`；本层不改 `make_report.py`，由 meta 转 i02）

现有三句话逐条给裁决。每条都带否证条件，写进报告时保留。

1. 现文「在文件字节接近的前提下，换方案（例如 IQ 系列 vs 传统 K 系列）分数会出现可测的差异」——**收窄**。匹配字节下只有少数格分得开：≤0.15 档共 35 格、31 格有区间、3 格区间不含 0（9.7%），而同一对内部的显著格方向不一致（Δ=0.154 的 LFM 那对：MBPP −0.103、MMLU +0.114）。建议改为：「同字节换方案只在个别格上分得开（本库 31 个有区间的匹配格里 3 格），方向随基准变；把比特预算与家族钉住后，方案效应在本设计下不可分辨（半宽 0.10–0.27）」。否证条件：补出第二个同字节方案对后同一方向的差在多数列上重复出现，或把半宽压到 0.05 以下仍跨 0。
2. 现文「而换厂商标签（同一模型、大小差不到 1%）基本测不出差异」——**保留方向、把「测不出」改成带半宽的「不可分辨」**。本库跨上传者、同尺寸、同协议的受控对只有 **1 对**（Qwen3.6-35B-A3B，Δbpw 0.025），九列全跨 0、逐列半宽 0.019–0.134；`attrib.py` 的 `bartowski` 系数也只由这一族识别，半宽 0.212–0.489，且符号与那一对在 3/9 列相反（外推假象，不得引用）。而那一对同时换了比特分配，所以它约束的是「上传者 + 分配这一整包」的上限。建议改为：「本库只有一对跨上传者受控对，差异小于每列 0.02–0.13 时不可分辨；样本 1 族，且该对同时换了分配」。否证条件：出现第二对并测出区间不含 0 的差。
3. 现文「结论：挑量化时应该比字节 / 方案，而不是比厂商标签」——**前半保留、后半改口径**。字节是唯一在本库 9 列上稳定不含 0 的变量（`slopes`）；「比方案」作为一个分数声明不成立（见第 1 条）；而标签真正代理的是**比特分配**（同字节下分配轮廓可差 0.34–0.43 比特/参数）。建议改为：「比字节（有效位宽）和比特落在哪类层上，不比档位名或厂商名」。否证条件：出现同分配、不同标签而分数差稳定显著的配对。
4. 现文「一眼可见 Qwen3.5-2B 组里 IQ2_XXS 明显垫底」——**保留观察、补语境**。那一组的单链聚类跨度是 0.843 比特/权重（3.266–4.109），按位宽尺子本身就值 0.150 的 HumanEval+ 分，而那 0.335 的实跳里有 45% 是预算；IQ2_XXS 同时也是组内位宽最低的那份（`cluster-2b`）。
