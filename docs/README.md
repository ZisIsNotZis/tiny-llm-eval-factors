# 量化 × 基准分数 —— 研究文档（唯一的文档来源）

## 这个研究是什么

量化（把大模型压到更低比特）之后，模型在各项任务上的**实际分数**会掉多少？这个"掉多少"
又取决于什么？做法是把每个可能的影响因素当成自变量 **X**（量化位宽、量化方案、模型规模、
KV 缓存精度、采样参数、投机解码深度、思考开关……），基准分数当成因变量 **Y**。

所有比较都在**同一个模型家族内部**进行：同一套 base 权重，只换量化文件，架构与参数量天然固定。
横轴统一用**有效位宽**（每个权重平均比特数 = 8×文件字节 ÷ 参数量），**从不使用 Q2/Q3 这类标称标签**
（它们实际跨度 2.76–5.04 bpw）。

非目标：排行榜、产品级推荐、自我训练、以困惑度（PPL）为目标。

## SSOT（唯一真实来源）

| 层 | 唯一来源 | 说明 |
|---|---|---|
| 数据 | `experiments.sqlite` | 唯一结果来源；一次运行一行 |
| 文档 | `docs/`（本目录） | 唯一文字知识来源；不得有两份文件讲同一件事 |
| 报告 | `report.html`（生成物） | 由 `make_report.py` 从 DB 生成，禁止手改 |
| 表格结构 | `.wrapup/mktables.py` → `build_tables()` | 只读 DB，返回结构化表，不产出 markdown |
| 项目规则 | `AGENTS.md` | harness 配置 |

**规则：任何"同一信息的另一种格式"都是垃圾。** 不维护 DB 数据的 markdown 副本；不解析 markdown 当数据源；
生成的报告/表格一律以 DB 为准，过期即删。

## 如何复现

```sh
python3 make_report.py            # 从 DB 生成 report.html（唯一报告）
python3 .wrapup/mktables.py       # 打印每张结构化表的行数/覆盖（不写文件）
python3 migrate_db.py             # 入库（唯一入库路径；只跑一次，跑完校验 total==distinct）
```
